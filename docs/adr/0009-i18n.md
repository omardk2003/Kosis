# ADR-0009: Internationalization (EN/DA)
Status: Accepted · 2026-11-11 · Owner decision D6

## Decision
- **next-intl 4** without locale-prefixed URLs. The app is authenticated, so SEO-friendly locale URLs aren't needed.
- **Locale resolution** (`src/i18n/negotiate.ts`): the `NEXT_LOCALE` cookie (the user's choice), then `Accept-Language`, then `en`. Later, the choice is also stored on the profile.
- **Messages** live in `content/messages/{en,da}.json`, owned by behavioral-product-specialist. Keys must be identical, which a unit test enforces. TypeScript types come from `en.json` (`src/i18n/types.d.ts`).
- **Rendering:** mostly server components. Client components get messages through `NextIntlClientProvider`.
- **Banned-word lint** covers both languages.
- **The OTP email is bilingual** (EN then DA), because Supabase templates aren't per-user localized.
- **Formatting:** dates and numbers go through `Intl`/next-intl formatters, never hand-written.

## Consequences
- Adding a language means adding a JSON file plus a value in `locales`.
- The client bundle includes the active locale's messages, which are small.
