## 2. Overlaps merged
- **Pause/archive timing:** AR-B1, PR-2 and QA-3 are the same root cause. PR-2 proposed "tomorrow only if today has an entry". AR-B1 proposed "always tomorrow". **AR-B1 was adopted** because it also closes the 23:59 exploit, and PR-2's case is a subset of it.
- **Replace and void rules:** AR-B3, AR-B4, PR-3 and QA-4 were merged into one rule. Both operations are allowed only within today−7…today, owner-bound and locked.
- **Grants and default privileges:** AR-B5, SR-H1 and QA-7 (H17 catalog test) were merged.
- **OTP:** SR-H2 and AR-N2 were merged. **Offline caching:** SR-H3 and AR-N3 were merged.
- **Read contract:** AR-B6 and PR-9 were merged.

## 3. Contradictions resolved
| Topic | Position A | Position B | Decision |
|---|---|---|---|
| Pause timing | PR-2: tomorrow only if today is done | AR-B1: always tomorrow | **Always tomorrow** (closes the exploit; simpler rule) |
| Test clock | AR-B5: `private.app_now()` overridden in local seed | QA-1: pass `p_now` into private functions | **QA-1**: no override code can exist in production |
| Replaced entry's `source` | QA-4: keep the original source | PR-3: `late` if `occurred_on` < today | **PR-3**: the full version was recorded later, so it's honest to label it late |
| Quote opt-in | spec v0.2: onboarding or Settings | UI-12: Settings only (onboarding stays ≤ 2 steps) | **Settings only** |
| Offline data | arch v0.2: cache the last data | SR-H3: no personal data in caches | **Shell only**. Offline shows data already in memory for the open session |
| Serwist | arch v0.2: Serwist | AR-N3: webpack/Turbopack risk, needs approval | **Hand-written `sw.ts`** (small scope, no dependency) |

## 4. Non-blocking findings applied in v0.3
- Integer arithmetic for floor/ceil (PR-6). §7.5 counts only entries that count toward `completed` (AR-N5).
- Aggregate chip copy (PR-7). Copy fixes: save-failure message, below-target recovery copy, minimum confirmation, Q14 wording, and removal of "lost" from AC-H6 (PR-8, UI-10).
- Reflection "updated by later logs" defined (PR-5). `upsert_reflection` validates the weekday and sets `updated_at` on the server (AR-N5).
- Timezone validation filter (AR-N1). `dismiss` key length cap. `reorder_habits` requires the exact set of the caller's habits (SR-M5).
- Export pagination and CSV formula escaping (SR-M4). RLS uses `(select auth.uid())`, plus the extra indexes (SR-L1).
- Ownership:
  - `docs/handoffs/` is create-only for all agents.
  - `vercel.json` is assigned to the lead-architect.
  - The generated types path is set.
  - The backend description's stale `db/` reference is fixed (AR-N4).
- Roadmap wording on delete exceptions and test layers (AR-N5).
- UI: Action Mode button hierarchy, accessible undo toast, focus ring offset, single OTP input, non-interactive chip, extra states (UI-7…14).
- QA: 360×640 viewport, banned-word lint, extra fixtures, H2 exception for `delete_habit` (QA-7…12).
