### B1 (medium): first-load JS is about 70% over the internal 110 KB gzip target
- `/`: 10 chunks, 186.0 KB. `/sign-in`: 11 chunks, 190.1 KB.
- Largest chunks: `.next/static/chunks/39_j1bdzreq0m.js` 69.9 KB, `0cz1d0mv5g_q7.js` 38.6 KB, `2xu0_-q1943mu.js` 35.8 KB (framework/runtime; next-intl and the Supabase/Turnstile client code are not attributed here).
- The home page ships the same JS as sign-in minus one chunk, so the baseline is the framework plus the global layout (`NextIntlClientProvider` in `src/app/layout.tsx`, `ServiceWorkerRegister`).
- Owner: frontend-engineer / lead-architect. Either trim (provider scoped to client components that need it, load Turnstile only when a site key is set) or decide the target is wrong for Next 16 and amend architecture section 8 via ADR. The check script is unchanged either way; I have not weakened it.

### Notes (not app bugs)
- Playwright 1.65 expects Chromium build 1254; the sandbox has 1243. `playwright.config.ts` falls back to the 1243 headless shell, or `PW_CHROMIUM_PATH`. CI with `playwright install` needs no override.
- Local auth config has `email_sent = 2` per hour (`supabase/config.toml:201`). The Mailpit-backed flow was not throttled in this run, but repeated runs may hit rate limits if SMTP is enabled. Watch for it.
- `vitest.config.ts` prints a Vite native-config-loader warning (no `"type": "module"` in package.json). Harmless.
