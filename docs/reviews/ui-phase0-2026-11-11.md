# UI review: Phase 0 screens (2026-11-11)

Reviewer: `ui-ux-designer` · Against: `docs/screens/sign-in.md`, `docs/screens/today-placeholder.md`, design-system v0.4 (incl. §11)

**Method note.** `design-taste-frontend` is intentionally not installed (§0, option A); §11 was used. This session had no shell tool, so **no screenshots were taken** and no server was started. This is a static review of source, tokens and copy. Re-run the 360/1280 light/dark capture before merge.

**Tokens.** `tokens.css` values are correct. Dark pairs verified: `--text-muted`/`--bg` 7.3:1, `--accent-contrast`/`--accent` 7.5:1, `--border-strong`/`--surface` 3.06:1. No change made. Tailwind `text-*` resolves to our tokens because unlayered `tokens.css` overrides the theme layer.

## Verdict: **APPROVE WITH CHANGES**

## BLOCKING

1. **Typed input is lost on every error** (S2, S7, S10, S11; §11.5 "nothing typed is lost"). In React 19, `<form action>` resets uncontrolled fields after the action returns. `src/features/auth/ui/sign-in-form.tsx:98-108` (email) and `:128-139` (code). **Fix:** make both inputs controlled (`useState` + `value`/`onChange`). On S7, select the code on refocus.
2. **Offline primary still submits** (S12). `sign-in-form.tsx:112` and `:141` set `aria-disabled={blocked}`, but `disabled` only covers `busy`, so a press or Enter while offline fires the server action. **Fix:** add `onSubmit={(e) => { if (blocked) e.preventDefault(); }}` on both forms (`:92`, `:123`). Link the offline reason (`:86`) to the button with `aria-describedby`.
3. **Focus is dropped on step change and errors** (S2, S5, S7, S13; WCAG 2.4.3). When the email form unmounts, focus falls to `<body>`. **Fix:** a ref plus effect on `state`. On step `code`, focus the OTP input. On `invalid_email`/`bad_code`, focus the field. On `/today` arrival, focus the `<h1>` (`tabIndex={-1}`), `today/page.tsx:20`.

## NON-BLOCKING

4. **No email echo on the code step** (S5). `sign-in-form.tsx:121-122`. **Fix:** render `state.email` (`--text-md`) with "Use a different email" above the OTP field, and move `:157-162` there.
5. **S8 folded into S7 (ADR-0006), but resend isn't next to the error.** The error is at `:140`. Resend comes after the primary (`:145-156`) and is an outline button. **Fix:** render resend as `btn-text` directly under the error line. During cooldown use `aria-disabled` only (drop `disabled`, so it stays focusable) and put the countdown in adjacent text, not the label. Copy request to product: `badCode` should cover expiry ("That code didn't work or has expired…"). Add a non-breaking space in "{seconds} s" (§11.4).
6. **Form-error pattern missing** (§8). The error sits below hint and captcha, with no 2 px `--text` border and no info glyph, and the hint isn't in `aria-describedby`. **Fix:** order label → hint → input → error (`:95-111`). Add `aria-invalid:border-2 aria-invalid:border-text` to `.field-input` and a 16 px glyph. Use `aria-describedby="{hintId} {errorId}"`.
7. **Primary button not in the display font** (§6). `globals.css:72-78`. **Fix:** `font-family: var(--font-display)`.
8. **Disabled opacity drops the label below AA.** Dark primary is about 3.5:1; light about 2.9:1. `globals.css:67-71`. This is exempt for inactive controls, but offline buttons carry meaning. **Fix:** keep full opacity and show `cursor: not-allowed` plus the visible reason.
9. **No shared app header; switch placement varies.** On sign-in the switch is above the h1 (`sign-in/page.tsx:39-41`); on Today it's beside the h1 (`today/page.tsx:19-22`). There's no app name and no `<header>`. **Fix:** one `AppHeader` (app name left, switch right) outside `<main>` on all routes.
10. **Language switch differs from spec §8.** Both languages render, and the current one is outlined (`language-switch.tsx:11-24`), which adds a boxed control to the header. **Fix:** render only the other language as `btn-text`, `lang` set, `aria-describedby` → hidden label. Not verified in a browser: switching keeps the step and typed values (S7 interaction).
11. **Today order and emphasis inverted.** `today/page.tsx:23-24`: the placeholder sentence is muted and the signed-in fact is primary (§11.4). **Fix:** h1 → signed-in line (`--text-muted`, check glyph) → placeholder (`--text`). Sign-out should be 48 px and full width at 360 (`sign-out-button.tsx:15`: add `min-h-[var(--control-height)] w-full sm:w-auto`).
12. **Hard-coded widths.** `sign-in/page.tsx:38` uses `max-w-[480px]`; the spec is `--form-max` 400. `today/page.tsx:17` and `page.tsx:10` use `max-w-[640px]`. **Fix:** `max-w-[var(--form-max)]` / `max-w-[var(--content-max)]`. The h1 `text-2xl` (32 px) should be `text-xl` per spec.
13. **`/` is a hero/splash** (§11.9, §11.12; unspecced): 44 px wordmark, tagline, "Get started". **Fix:** redirect `/` → `/today` (the proxy already routes signed-out users to sign-in), or request a spec.
14. **Layout shift risk.** The Turnstile mounts without reserved height (`:65-73`), and resend mounts it after cooldown (`:147`). **Fix:** wrapper `min-h-[65px]` when a site key is present.
15. **`/offline` copy repeats** "You're offline" in the title and body (`en.json` `offline.*`). Copy request to product. The page is vertically centered (`offline/page.tsx:9`); top-align it for consistency.
16. **OTP paste.** `maxLength={6}` (`:134`) truncates "123 456" before normalization. **Fix:** strip non-digits in `onChange`, and keep `maxLength` off or at 7.

Tone: no banned words, no guilt language. Filled primary: exactly one per view (none on Today) ✓. Targets: `.btn` ≥ 44 px, inputs 48 px ✓. Focus ring is visible in both themes ✓.
